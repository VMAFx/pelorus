feat(vulkan): cross-vendor "via Vulkan" QP-map steering (ADR-0114 Tier 2)

Patch libavcodec/vulkan_encode.c to drive VK_KHR_video_encode_quantization_map
so one Pelorus map producer (vf_pelorus_analyze roi=1, emitting the standard
AV_FRAME_DATA_REGIONS_OF_INTEREST) steers bit allocation on every
Vulkan-encode-capable GPU (h264_vulkan / hevc_vulkan / av1_vulkan), zero host
roundtrip. Adds a `pelorus_roi` AVOption (default off) in the shared
VULKAN_ENCODE_COMMON_OPTIONS macro, so all three codecs expose it at once.

Two driver-probed map kinds, picked by the negotiated rate-control mode:
  - DELTA map (R8_SINT) under CQP: signed per-texel-block ΔQP, the direct
    analogue of the Tier-1 NVENC qpDeltaMap / QSV mfxExtMBQP delta maps;
  - EMPHASIS map (R8_UNORM) under CBR/VBR: a [0,1] per-block emphasis that the
    analyze 0..1 banding score maps onto almost directly.

The ROI side data is coalesced into a compact, texel-block-aligned rectangle
list (same qoffset->ΔQP convention as the NVENC/QSV patches: qp_range =
51 + 6*(depth-8), reverse region precedence) and the map texel image is filled
ON THE GPU: the canonical build-time pelorus_qpmap.comp.glsl compute shader
reads the rect SSBO and imageStores the per-texel delta /
emphasis directly, then a GENERAL -> VIDEO_ENCODE_QUANTIZATION_MAP_KHR barrier
hands it to the encode. The dispatch records on the encode command buffer, so it
is used only when the encode queue family also advertises VK_QUEUE_COMPUTE_BIT
(no cross-queue ownership transfer); otherwise a host raster + staging-buffer
vkCmdCopyBufferToImage fallback runs. Either way the map is bound at
vkCmdEncodeVideoKHR by chaining VkVideoEncodeQuantizationMapInfoKHR with the
WITH_*_MAP flag; the session is created with the matching ALLOW_ENCODE_*_MAP_BIT
and the session parameters carry the probed quantizationMapTexelSize.

Device enablement: stock FFmpeg enables neither the extension nor its
videoEncodeQuantizationMap feature, and both are required
(VUID-VkVideoSessionCreateInfoKHR-flags-10264). This patch therefore adds the
extension to libavutil/hwcontext_vulkan.c's optional device-extension table
(new FF_VK_EXT_VIDEO_ENCODE_QUANTIZATION_MAP flag + loader mapping) and chains,
copies and enables the feature struct, so an FFmpeg-created device turns both
on whenever the driver supports them. The probe requires both.

Valid usage: the map image is created with the advertised tiling of a format
entry whose usages cover the fill path (NVIDIA advertises R8_SINT in LINEAR
tiling only); the map copy/dispatch is recorded before vkCmdBeginVideoCodingKHR
(transfer and compute commands are invalid inside a video coding scope); the
session parameters are created QUANTIZATION_MAP_COMPATIBLE; and hevc_vulkan sets
cu_qp_delta_enabled_flag whenever a map is bound, without which a CQP stream is
undecodable. Delta-map values are clamped to the driver-reported per-codec range
(min/maxQpDelta, min/maxQIndexDelta), since a value outside it leaves the block
QP undefined; NVIDIA reports [0, 51] for H.264/H.265, so lower-QP requests clamp
to 0 there and the probe warns.

Generality (product patch for all vendors, no device assumptions): the whole
path is runtime-probed — the extension and feature must be enabled, the codec
must advertise the delta/emphasis capability flag, and a usable map format,
tiling and texel size must be returned by GetPhysicalDeviceVideoFormatPropertiesKHR.
Any miss degrades to a one-shot warning + pass-through. A frame with no ROI side
data binds no map (zero behaviour change). The path is also compile-gated by
VK_KHR_video_encode_quantization_map so older Vulkan headers build to a clean
no-op.

VERIFICATION: vulkan_encode.c, the three vulkan_encode_{h264,h265,av1} TUs and
hwcontext_vulkan.c build clean under FFmpeg's warning set; the canonical
build-time GLSL and Pelorus's standalone reference shader compile under glslang.
On an RTX 4090 (NVIDIA 615.71.09) h264/hevc/av1_vulkan bind the map on every
ROI frame with no validation-layer error beyond the stock encoder's own; a
+0.3 qoffset region raises the decoded H.264 macroblock QP from 30 to ~45 there
and the other half stays at 30 (ADR-0166). RADV (Mesa 26.2.4) advertises only an
R32_SINT map without a fillable usage, so the probe disables steering there.
