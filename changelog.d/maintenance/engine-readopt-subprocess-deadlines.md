- The Praetor engine is re-adopted at 4e6c6d9cbf9c (devcontainer bundle and the `standards-gate.yml` pin). Its HISS-02 check now flags a Python `subprocess.run` call that passes no `timeout=`. Each of the 33 calls it flagged, across 11 files in `scripts/`, now takes its deadline from a named module constant (`*_TIMEOUT_S`) that fits its Meson test timeout, so the debt baseline stays at 0 infractions. On Windows, `scripts/run-meson-test.py` now stops a `meson test` child still running after 30 minutes, together with every test process it started, and exits with status 124. Meson runs in a Windows job object it joins before it starts, so the stop also reaches test processes that broke away from the nested job of pip's console-script launcher, and still works when Meson exits just after the deadline. The C harness of the patch tests (`scripts/patch_harness.py`) uses the same job object in place of `taskkill /T`, and its `patch-harness` test now requires the stalled compiler's child to be gone on Windows too. A tree step that cannot reach the tree is named on stderr rather than falling back silently. The new fast-suite test `scripts/test-run-meson-deadline.py` checks these paths with live processes on the Linux CI leg and the three Windows legs (MSYS2, clang-cl, MSVC) ([ADR-0246](docs/adr/0246-meson-testlog-credential-scrub.md)). `scripts/bench/run-bench.py` now runs each FFmpeg step under `--ffmpeg-timeout` (default 1800 s). The HISS-02 scan passes a call that forwards keyword arguments through `**` as undecidable, which had hidden the missing deadline there. The new Semgrep rule `pelorus-py-io-unpack-deadline` closes that gap. It also reports a `timeout=None` next to the unpack and a `kw["timeout"] = None` before it. A `kw.setdefault("timeout", ...)` does not satisfy the rule, because it keeps a `None` the caller passed. `scripts/test-semgrep-io-unpack-deadline.py` checks the rule against planted cases. The process-tree stop now lives in one place, `scripts/process_tree.py`, shared with `scripts/patch_harness.py`. The new fast-suite check `scripts/check-python-dual-import.py` refuses a Python file that imports one module with both `import` and `from ... import`, which CodeQL otherwise reports only after a push.
