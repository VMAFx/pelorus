- The hourly changelog render workflow `.github/workflows/changelog-render-pr.yml` treats GitHub's `schedule` trigger as best effort: from 2026-11-10 to 2026-11-16 it started 22 scheduled runs in 145 hourly slots, 4.1 h to 8.9 h apart. The 6 h owed-age decision opens the render pull request on the next run that starts and passes its settings check, so each dropped window costs one gap; the latest open came 14.0 h after the debt began, and the sample's worst case is 15.3 h counting the measured 22 min maximum runner queue wait (14.9 h without it), 4.7 h inside the 20 h pull request check. GitHub sets no upper limit on schedule delay, so that check and the 24 h push check stay the backstop ([ADR-0259](docs/adr/0259-render-schedule-best-effort.md), amends [ADR-0252](docs/adr/0252-scheduled-changelog-render-pull-request.md), [#631](https://github.com/VMAFx/pelorus/issues/631)).
