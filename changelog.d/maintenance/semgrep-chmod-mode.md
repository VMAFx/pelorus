- File permissions set by `os.chmod` and `Path.chmod` grant owner access only (`0o600` or `0o400` for data, `0o500` for stubs), avoiding group and other permissions flagged by CodeQL and modes above `0o650` flagged by Codacy Opengrep. The Semgrep rule `pelorus-chmod-owner-only` enforces owner-only permissions across tracked Python files, and `scripts/test-semgrep-chmod-mode.py` proves the rule on planted cases in the fast suite and the CI semgrep job. The fast-suite installer removes an earlier runner before writing it again, since an owner-only runner cannot be overwritten.
- The Semgrep rule `pelorus-chmod-owner-only` flags inherited file modes constructed from `st_mode` (`$X.st_mode | ...`, `$S.stat().st_mode | ...`, `os.stat(...).st_mode | ...`, or a local `st_mode` OR'd) to prevent inheriting unknown group or other bits, and reports that the mode must be set explicitly.
- A new check `scripts/check-semgrep-harness.py` and fast-suite test verify that every tracked Semgrep test script loads `scripts/semgrep_harness.py` dynamically and does not duplicate `run_semgrep`, `scrubbed_env`, `resolve_executable`, or `ScanError` at module level.
- Git-dependent Semgrep tests skip Windows CI, where MSYS2 UCRT64 does not put git on PATH; the harness-use self-test still runs on every platform. Harness discovery reuses `scripts/tracked_python.py`, and `scripts/check-meson-windows-git.py` enforces Windows guards with planted negative cases and a git-free fast-suite check on every platform.
- Snapshot cleanup skips symlinks before making retry targets writable, preserving permissions outside the snapshot while still making its parent writable. The fast-suite test `writable-retry-symlink` (`scripts/test-writable-retry.py`) removes a planted read-only snapshot holding a symlink and fails if the link target's mode changes. The rmtree callback audit found no other handlers; a syntactic Semgrep rule cannot reliably resolve callback bindings and prove that a symlink guard covers each chmod call.
- Mandatory tracked-file scans refuse empty lists with exit code 2, including Semgrep test discovery, Python marker discovery, suppression marker discovery, and repository-name discovery. The harness self-test plants an empty selection to verify the shared refusal.
- The harness-use check requires literal `hermetic=True` for planted-tree scans and `hermetic=False` for `ROOT` or `REPO_ROOT` scans, with planted failures for wrong, missing, or dynamic flags. Shell-splice fixtures now keep their full scan coverage when temporary directories live inside a Git worktree. Shared scans use at most four workers.
