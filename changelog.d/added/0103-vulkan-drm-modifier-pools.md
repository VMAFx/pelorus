- `tiling=drm` on the six Pelorus filters that write new frames (`deband`, `denoise`, `dehalo`, `aa`, `deblock`, `borderfix`): the output pool uses DRM format modifier tiling with DMA-BUF export, so `hwmap=derive_device=vaapi` (and QSV through VAAPI) takes the frames without `hwdownload`. The driver picks from the storage-capable modifiers without auxiliary planes, narrowed by the new `drm_modifiers` option; when none fits, the filter substitutes `DRM_FORMAT_MOD_LINEAR` and names it in a warning, and it never falls back to OPTIMAL tiling. The default `tiling=optimal` keeps FFmpeg's pool. NV12, including odd sizes, maps bit-exact on an Arc A380 (VAAPI and QSV). On AMD Vulkan drivers the filter warns that mapped frames can be read unfinished (14-17 of 20 frames on a Radeon 610M) until FFmpeg's map synchronisation is fixed; P010 to VAAPI needs an FFmpeg import fix queued in VMAFx/ffmpeg-patches ([#103](https://github.com/VMAFx/pelorus/issues/103), ADR-0184).
