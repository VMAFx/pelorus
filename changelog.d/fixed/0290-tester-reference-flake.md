- The tester's `sidedata_roundtrip` stage no longer fails a healthy carrier because its own reference blob came back short (#290, tool 0.4.9). The cause: FFmpeg's progress line is written by another thread and landed in the middle of the `showinfo` hex dump of the reference run, so the parser read a few kilobytes of a 12 408-byte blob. The reference and decode-tap runs now pass `-nostats`; each reference blob is checked against its own header `total_size` and the picture count, read once more when short, and a second failure ends the stage as `incomplete` (a harness error), never as a carrier `fail`. New self-test rules `sd_reference_length` and `sd_reference_not_carrier_fail`. Measured on an RTX 4090 (`hevc_vulkan`, four flat cases, progress lines forced every 0.5 ms to mimic a slow GPU): the old tester failed 50 of 50 loops, the new one passes 50 of 50.
