# ADR-0178: Every tester image file has a recorded licence, a gate fails the build on an unrecorded one, and the tester CI runs only on image inputs and never publishes from a schedule

- **Status**: Proposed
- **Implementation**: pending (#236)
- **Date**: 2026-10-09
- **Deciders**: Lusoris
- **Tags**: licensing, supply-chain, ci, release, tester

## Context

[ADR-0173](0173-tester-programme.md) fixes the tester programme and
[ADR-0176](0176-rc-process-and-tester-publish.md) the publish workflow. Nothing
yet records what the tester image contains. The image holds a patched FFmpeg
(GPL-3.0-or-later), `libpelorus` (EUPL-1.2), Debian packages under many
licences, the Vulkan loader and a Python interpreter, and its vendor variants
will add proprietary runtimes with their own redistribution terms. The first
`tester-publish` dispatch, which a `v0.4.0-rc.1` candidate needs, would publish
those bytes. The same workflow also costs hosted minutes: a patched FFmpeg
build per run, and it started on every pull request that touched a path in its
filter.

The precedent is VMAFx's tester licence gate (VMAFx ADR-1503, ADR-1514). Its
record covers Python wheels, grafted libraries and Go modules the Pelorus image
does not have, so the Pelorus record is smaller.

## Decision

**1. A licence record.** `tools/tester/licensing.json` lists every component of
the tester image: id, name, version, SPDX expression, the paths it owns (globs),
where its source is, and whether it may be redistributed. A licence registry in
the same file names each SPDX identifier in use, whether it is redistributable,
and the licence text that ships in the image; identifiers such as
`LicenseRef-nonfree` are present with `redistributable: false` so that using
one fails. Debian files are not listed by hand: a file owned by an installed
dpkg package is recorded by that ownership, and the package must carry a
non-empty `/usr/share/doc/<package>/copyright`. Fixtures are not duplicated:
the record's `tester-fixtures` component points at `fixtures.lock.json`, which
already pins each fixture's bytes and licence, and the gate reads it.

**2. A gate in the image build.** `tools/tester/licensing.py check` runs in a
`licence` stage of `tools/tester/Containerfile` on the finished tree, and the
`runtime` stage takes the notices file from that stage, so the image cannot be
built without the gate passing. It fails on a file that no component, dpkg
package or ignore rule owns, a component whose licence is not in the registry or
is not redistributable, a Debian package without a copyright file or from an
archive component other than `main`, a licence text missing from the image, a
component that matches no file, a source file whose SPDX header differs from its
component, and a notices file that is absent or stale. Ignore rules (package
manager state, container-runtime mounts, generated bytecode) each name a reason
and an expiry date; the gate fails after the date. Its `self-test` plants each
defect in a fake tree and must see it refused; the stage runs it first, and
`meson test --suite=fast` runs it too. Standard library only, so the gate needs no
packages beyond the interpreter.

**3. Notices inside the image.** `licensing.py notices` writes
`/usr/share/licenses/pelorus-tester/THIRD_PARTY_NOTICES.txt`: the Pelorus
repository and exact commit (EUPL-1.2 Article 5), the FFmpeg remote and commit,
the location of the corresponding source (the `-source` image), every
component with its licence, every Debian package with its version and declared
licence names, and the fixtures with their attribution. The publish workflow runs
the check again on the built image.

**4. The patch archive ships a NOTICE.** The release archive already carries
the LGPL-2.1-or-later and EUPL-1.2 texts. `scripts/release/write-patch-notice.sh`
adds a `NOTICE` that maps paths to licences and names the release commit and
the FFmpeg base commit; `check-build-config.py` requires the step.

**5. Bounded CI cost.** `tester-publish.yml` runs on pull requests only when a
path the image is built from changes (the tester tools, the patches,
`libpelorus`, the Meson files, `build-config.env`, `LICENSES/`, `REUSE.toml`, the
workflow); `check-build-config.py` evaluates the filter against sample
docs-only and image-input paths. A nightly schedule builds without pushing: only
the `build` job can run on it, `validate` and `publish` run on `workflow_dispatch`
alone, and the linter refuses a `schedule` or `always()` in either. Every job has
a numeric `timeout-minutes` no larger than its cap (build 90, validate 10,
publish 150). The runbook records the cost expectations.

## Alternatives considered

| Option | Pros | Cons | Why not chosen |
| --- | --- | --- | --- |
| Port VMAFx's `licensing.py` whole | Same tool both sides | 1,800 lines for wheels, grafted libraries and Go modules the image lacks; needs third-party Python modules | A smaller record fits the image; the model (record, ownership, notices, self-test) is kept |
| Generate the record from an image scan (Syft or ScanCode) | No hand-kept list | Scanners report; they do not decide what may ship, and a scan has nothing to fail against | A scan can feed an SBOM, not the redistribution decision |
| Parse each Debian copyright file for its licence | Per-package verdict | Hundreds of free-form names across the base image; the parser would be the part that breaks | Debian `main` is DFSG-free by archive policy; the gate checks the archive component and the copyright file |
| Check only at publish time | One place | A planted file is found after the build minutes are spent, and pull requests would not see it | The Containerfile stage fails every build, including a pull request's |

## Consequences

- **Positive**: a new package, library, file or licence fails the build until it is recorded; the image carries its own notices; the first dispatch ships the record; docs-only pull requests and the nightly cost nothing beyond the filter.
- **Negative**: every change to the image contents edits `licensing.json`; ignore rules expire and need renewal (the first expires 2027-04-09); the nightly build spends hosted minutes (one amd64 build a day).
- **Neutral / follow-ups**: vendor images (#229, #230) add components and a vendor-licence ADR; `pelorus-dev` is not covered by the gate ([research 0236](../research/0236-tester-artifact-licence-audit.md)); the first dispatch measures the build duration for the runbook.
