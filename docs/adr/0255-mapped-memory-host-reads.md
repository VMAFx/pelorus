# ADR-0255: Copy mapped device memory before element-wise host reads

- **Status**: Accepted
- **Date**: 2026-11-11
- **Deciders**: Lusoris
- **Tags**: vulkan, performance, zero-copy

## Context

The [motion-estimation wall-time measurements](../metrics/mc.md) attribute almost all of the old host cost to two operations: the O(n²) p95 scan and element-wise reads of mapped GPU buffers. PR #545 guards the p95 half with `ffmpeg-patches/test/mc_stats_test.c`; it cannot detect a caller passing mapped memory directly to `attach_motion()` again. The current `mc_snapshot()` in `ffmpeg-patches/files/vf_pelorus_mc_vulkan.c` copies each mapped span once before host processing. Issue #458 needs that second half held too.

The existing [device-local allocation rule](0222-device-local-storage-buffers.md) already scans the relevant C files, headers and added side of hand-maintained patches. The same scan can reject direct mapped reads without a GPU runner.

## Decision

Extend `scripts/check-vulkan-buffer-domain.py`, fast test `vulkan-buffer-domain`, to classify every `mapped_mem` token after line splicing and comment/literal masking in `scripts/c_scan.py`. Classify each patch hunk as an independent region with its own masked new-side text and added-line origins. Hunk header counts delimit regions, as `git apply` does: statements, calls, arguments, alias tails and flag resolution cannot cross them. Blank prefix offsets preserve patch line numbers. Only context and added lines enter lexing and splicing, joined directly in new-side order; excluded patch positions are restored as blank output lines afterward. A splice run containing any added line marks the output line holding its joined text as added; its origin follows the previous new-side line, skipping removed lines and metadata. Report refused mapped uses only when their classification region overlaps an added line: statement start through statement end, extended through the scanned block tail for an alias declaration (through the available text when the closing brace is absent). Apply the same overlap requirement to allocation calls, from the call start through the closing parenthesis. Context-only sites remain unreported.

Use one nesting implementation for argument splitting and argument indexing. Parentheses, brackets and braces all change depth; only commas at depth one separate arguments, and the closing parenthesis returning depth to zero ends the call. Each allowed bulk or sink pointer expression must contain exactly one `mapped_mem` token before casts are stripped. Permit complete pointer expressions only in `memcpy` arguments 0 and 1, `memset` argument 0, and the documented write-only argument 3 of `pel_mc_build_predictors` (`pelorus_mc_stats.h:66–84`) and `pelorus_qpmap_raster` (`vulkan-pelorus-qpmap.patch:1313–1345`); indices are zero-based. Member-qualified callees are refused. A mapped destination passed to `memcpy` or `memset` is allowed only when the call is the whole expression statement, optionally prefixed with `(void)`, because those functions return their destination. Permit plain cast stores and non-const local aliases only with allow-listed declaration specifiers and when every later alias use starts a statement and is a plain indexed store. The type allow-list comprises C qualifiers and scalar specifiers, `struct`/`union`/`enum` plus a tag, names ending in `_t`, and names starting with an uppercase letter. Refuse other uses, including compound assignments, and require one bulk `memcpy` before element-wise host reads. Keep three exact-file, exact-statement exceptions for issue #596, entered 2026-11-11 under MEL category D (120 days):

| File under `ffmpeg-patches/files/` | Exact statement after whitespace collapse | Reason |
| --- | --- | --- |
| `vf_pelorus_analyze_vulkan.c` | `base = (const uint32_t *)buf_vk->mapped_mem;` | Per-tile reads scale with resolution |
| `vf_pelorus_denoise_vulkan.c` | `*acc_out = (const PelorusDenoiseBuf *)buf_vk->mapped_mem;` | Fixed 160-word accumulator |
| `vf_pelorus_grain_estimate_vulkan.c` | `if (err >= 0) err = attach_estimate(s, in, (const PelorusGrainBuf *)buf_vk->mapped_mem);` | Fixed statistics struct |

Each exception must cover exactly one refused site. Zero matches, duplicate matches, duplicate `(file, statement)` entries, unknown MEL categories and dates after 2027-03-11 fail the check; 2027-03-11 remains allowed. The pure `check_known()` receives its date explicitly; the CLI supplies today's date. An empty mapped-use scan also fails. `--files DIR` selects a source copy for both allocation and mapped-read checks; its default remains `ffmpeg-patches/files`.

Parse hunk headers with `^@@ -(\d+)(?:,(\d+))? \+(\d+)(?:,(\d+))? @@`, allowing trailing section text and defaulting omitted counts to one. Open a new hunk only outside a body. Consume context lines, including empty lines, from both counts; removals from the old count; additions from the new count; and backslash markers from neither count. Header-shaped body lines remain body lines, including a removed decrement followed by an added increment. Finish a body only when both counts reach zero. Fail closed on an unknown body prefix, a negative count, EOF before completion, a malformed outside-body `@@` header or a patch without any hunk. Report one `file:line: unreadable patch hunk ...` diagnostic per unreadable patch through both `check()` and the CLI. Outside bodies, accept only the full-line shapes in `_patch_metadata()`: `diff --git a/\S+ b/\S+`; `index` with two lowercase hexadecimal object names separated by `..` and an optional regular-file mode `100644` or `100755`; `new file mode` with either of those modes; `--- a/\S+` or `--- /dev/null`; and `+++ b/\S+`. Hunk headers go through the counted parser; a backslash-space marker is accepted immediately after a completed body. Reject every other outside-body line, including blank lines and trailing additions. The allowed modes mirror the shapes used in the live tree. Mode `120000` makes `git apply` write a symlink and `160000` a gitlink; neither is C source the lexer can classify. This allow-list is necessary because `git apply` acts on some outside-body sections: `GIT binary patch` writes decoded file content. These boundary behaviors were measured with Git 2.56.0; the [research digest](../research/0458-mapped-read-guard.md#git-apply-boundaries) records the cases. Removed lines and no-newline markers are excluded from lexical input and restored as blank output at their original patch positions. Comment masking preserves width with spaces. Source loading and unified-patch parsing live in `scripts/c_source.py`; lexing, generic statement boundaries, pointer-chain checks and alias-tail scanning live in `scripts/c_scan.py`. Imports go from the source reader to the lexer, and the checker runs both modules' self-tests. The reader decodes strict UTF-8, splits on LF only, and permits non-control characters, LF and tab. Invalid UTF-8, other control characters and every trigraph fail closed with a line-numbered unreadable diagnostic before masking, including `??'` where an untranslated quote would mask a mapped read. ISO C17 compilers translate trigraphs in phase 1, including in comments and literals, and treat lone CR as a line end; `git apply` splits on LF only. Measurements on `56ba1af` used Git 2.56.0, GCC 16.2.1 and clang 23.1.4 with `-std=c17 -E -P`; the digest records the patch and compiler bypasses. Both `argument_index()` and `call_args()` derive their positions from `argument_spans()` so nested commas cannot shift one rule independently of the other. Self-test cases accept an alias whose first store has an empty prefix and a direct cast store after a closing block, and keep a spaced patch pre-increment without a preceding file header as added code. The [research digest](../research/0458-mapped-read-guard.md#self-test-strength) records all 97 non-equivalent checker rule mutants and ten Semgrep rule or importer-test mutants exiting 1, including independent removal of each of those three boundaries, and the final file hashes and NLOC counts.

## Alternatives considered

| Option | Why not |
| --- | --- |
| Runtime timing test on a GPU | Needs a GPU runner; GPU wall-time regression coverage remains in #167 |
| clang-tidy or Semgrep rule | No project rule engine for this C flow; the existing regex scan already owns these files |
| Review only | Does not mechanically prevent the direct mapped argument from returning |

## Consequences

- **Positive**: The fast test rejects new direct mapped readers while preserving bulk copy-out, uploads and documented write-only sinks. Its self-tests plant readers, alias escapes, read-modify-write operations and exception failures. Fixtures are written as bytes so the self-test runs unchanged on Windows; the Semgrep rule `pelorus-strict-reader-fixture-bytes` refuses text-mode writes through `write_text`, `open`/`Path.open`, `NamedTemporaryFile`/`TemporaryFile`/`SpooledTemporaryFile`, `fdopen` and every `TextIOWrapper` call in an explicit path list covering the reader modules and every tracked Python importer; `scripts/test-semgrep-strict-reader-fixture.py` keeps that list equal to the reader modules plus the importers found by parsing every tracked Python file, and the scanned C/H sources are checked out with LF.
- **Negative**: This is a lexical scan, not a C parser. Digraphs and `##` fail closed in raw text, including literals and comments, like trigraphs; a spliced, comment-masked directive naming `mapped_mem` also fails closed when its logical line overlaps an addition or belongs to a C/H source. Macros are still not expanded: a function-like macro whose body does not name `mapped_mem` is outside this rule only when its call site also hides the token, which the directive and paste refusals prevent; universal character names remain untranslated. CRLF sources fail closed. A whole-file regex import scope was rejected because Semgrep's regex engine stops matching on large files without an error: no finding when about 16 KB precedes the import. Module names computed at run time and path-based loading (`importlib.util.spec_from_file_location`) are outside the rule's scope; no tracked script loads the reader modules either way. C23's removal of trigraphs does not apply: the pinned FFmpeg `n9.0.2` configure (`build-config.env`) defaults to `-std=c17` (`stdc_default="c17"`, line 4412). Spliced newlines are restored after the next surviving newline, or at EOF, to preserve line counts. Unterminated string/character literals remain unmasked up to their newline or EOF; unterminated block comments remain unmasked through EOF. C23 digit separators such as `1'000` are treated as unterminated character literals, leaving that line unmasked. Bulk destination calls embedded in assignments, conditions or arguments fail closed; so do keyword-led pseudo-declarations (`return`, `else`, `do`) and alias stores within chained assignments or call arguments. The backward `enclosing_call()` scan stops at `}`, so `pel_mc_build_predictors(h, (S){a, b}.w, n, (int32_t *)b->mapped_mem, &gx, &gy);` is refused even though argument 3 is the write-only sink. The default check reads only `ffmpeg-patches/files/`; it does not scan the shared FFmpeg fix series that `scripts/fetch-ffmpeg-series.sh` applies first. The lexical scan fails closed on `mapped_mem + off`, even when a particular offset could be safe. Keyword parentheses (`sizeof`, `if`) around `mapped_mem` and calls through parenthesised names also fail closed. Pointer provenance from `vk->MapMemory` and wrapper implementations is not followed; the rule is not a general C data-flow analysis.
- **Neutral / follow-ups**: Issue #596 replaces the three known reads with copies before their exceptions expire. GPU wall time remains with #167. The patch stack and runtime code remain unchanged.
